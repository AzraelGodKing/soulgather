## v6.10.1

- Patch: milestone gifts are no longer skipped after a Reset (see the fix at the end of this entry). Footer/CSS **v6.10.1**; save key unchanged.
- The bullets below are the AZR-194 module split and follow-up cleanups, which do not change behavior.
- Module split, step 1: constants, tables and normalisers move to `js/config.js` (`SoulgatherConfig`); pure cost/mult/rate maths moves to `js/economy.js` (`SoulgatherEconomy`), which never reads `state` or the DOM. `game.js` keeps thin wrappers that pass `state` in (e.g. Favor for the AZR-181 cost multiplier), so the public `SoulgatherEconomy` API and all numbers are unchanged. Still classic `<script>` tags, still runs from `file://`.
- Step 2: the persistence layer moves to `js/state.js` (`SoulgatherState`): the `FIELDS` manifest, `freshState`, `serializeState`, load sanitisers, `isSaveShape` and the `applySaveData` migrations. Every function takes the state object as an argument and never touches the DOM or `localStorage`; save I/O, backups and the load-failure notice stay in `game.js`. Field loaders now receive the target state (`load(raw, s)`), so `vowsKnown` seeding no longer reads a global. The v6.9 fixture round-trips byte-for-byte against `main`.
- Step 3: the 101 player-action handlers (buys, rites, edicts, Crown/Remembrance, vows, aspects, autobind toggles, timed bursts, and `layTribute` with its phase helpers) move to `js/actions.js` (`SoulgatherActions.create(host)`). Handlers read and replace state through `host.getState()`/`host.setState()` and request every page effect (toasts, announcements, confirm dialogs, render, save, card reveals) through host hooks, so `actions.js` has no `document`, `window` or `els` references. A differential run of every handler from four starting saves plus a 325-step sequence matches step 2 exactly.
- Step 4: the view layer moves to `js/ui.js` (`SoulgatherUI.create(host)`): `render`, `renderStats`, `renderChronicle`, `renderNames`, card reveal/hide helpers and the `REVEALABLE` table, the toast queue (including gift batching and Escape dismissal), the screen-reader announcer, ripples and text formatting. The UI reads state through `host.getState()` and never writes it; the four one-time unlock toasts set their saved flag through `host.claimFlag()`. `game.js` drops to about 3,800 lines. The same differential, extended with `render` and the card reveals, matches step 3 across 460 cases and 343 sequential steps.
- Step 5: the entry point moves to `js/main.js`, loaded last: `boot`, the frame loop (`tick`), the `HOTKEYS` table and `resolveHotkey`, the keydown handler and all DOM event binding (`bind`). `game.js` no longer boots itself; it publishes `globalThis.SoulgatherGame` (state getter, the actions and UI instances, and the engine functions `main.js` calls). `main.js` reads state live through `getState()`, so click and hotkey handlers keep working after a reset or import replaces the state object. Frame-clock and render-due bookkeeping stay beside the dirty flags in `game.js` (`frameDt`, `takeRenderDue`). 144 aliases that `game.js` no longer used were dropped; `game.js` is now about 2,800 lines and `main.js` about 1,070. Load order: `num.js`, `format.js`, `config.js`, `economy.js`, `state.js`, `actions.js`, `ui.js`, `game.js`, `main.js`. The new **Architecture** section above documents the files, the `create(host)` wiring and the purity rules; the CI paragraph now lists all six test suites.
- File-size trim, part 1: the 100 timed-burst, edict, Crown and Remembrance cost functions move from `economy.js` to `js/edicts.js` (loaded just before it); `economy.js` merges them back, so `SoulgatherEconomy` has the same 174 keys and every function returns the same values (checked over 10,440 calls). `economy.js` drops from 1,771 to about 1,140 lines.
- Part 2: the 50 prestige handlers (Reliquary edicts, Crown/Remembrance shop, Tribute and its phases) move from `actions.js` to `js/prestige.js` (loaded just before it). `SoulgatherActions.create()` builds the prestige module with the same host and merges its handlers, so `game.js`, `main.js` and the action object keep every key. The action differential matches part 1 across 460 cases and 343 steps. `actions.js` drops from 2,031 to about 920 lines; `prestige.js` is about 1,150.
- Part 3: `game.js` sheds 144 test-export lines that re-assigned economy functions onto the object they came from, and copies its 106 config/state test constants with two key lists instead of one line each. Unlock checks, the Chronicle, milestone gifts, bound names and peak tracking move to `js/progression.js` (`SoulgatherProgression.create(host)`, built between the UI and the actions); the `GIFTS` table and its indexes move to `config.js`. The action differential, extended with `applyDt` (1 s, 30 s, 1 h), `checkUnlock`, `tryMilestoneGifts`, `syncChronicle` and `tryNamesBound`, matches part 2 across 488 cases and 364 steps. `game.js` drops from 2,790 to about 1,450 lines.
- Part 4: the Rites, Marks, Aspects, Vows, Reliquary and Crown blocks of `render` move unchanged into per-panel functions in `js/panels.js` (`SoulgatherPanels.create(ui)`, loaded just before `ui.js`); `ui.js` builds it with the helpers those panels use and calls them in the same order. A render differential, recording the text, disabled flag and classes of all 402 bound elements after every case, matches part 3 across 488 cases and 364 steps. `ui.js` drops from 2,635 to about 1,260 lines; `panels.js` is about 1,470. Every file is now under about 1,500 lines.
- Fix (found during the split, predates it): Reset, Start Fresh after a failed load, and the load-failure fallback now clear the milestone-gift cache. Before, they replaced the state but kept the old count of ungranted gifts; once that stale count reached zero with all twelve names bound, every remaining gift was skipped until the page was reloaded. Tribute was never affected. `test-gifts` Test 19 covers it.
- Cleanup: dropped unused `markRenderDirty`, `beginKnell` and `SAVE_FIELDS`, and the `formatGoalNum`/`formatBlessing` fallbacks for a missing `SoulgatherFormat` (it always loads first).
- Also removed the unused AZR-166/179 leftovers: the ten `bumpPeak*` helpers, `GIFT_FLAGS`, `bulkCostLoop`/`wellBulkCostLoop`, and `SoulgatherNum.make`/`min`.
- The 29 Favor shop buyers in `js/prestige.js` now share one `buyFavorUpgrade(levelKey, costFn, chronicleId)`; each public `buy*` name stays as a one-line wrapper (Edict of Echoes keeps its one-time cap). `buyEdict` and `buyMemory` gain the same non-finite-cost guard as the rest.
- The 22 identical `...Starts...` level checks in `js/edicts.js` (timed-burst edicts, Quiet Court and the autobind edicts) are one `autobindStartsPredicate(level)`; `SoulgatherEconomy` exposes that instead of the 22 names.
- Further cleanup (no behavior change): unused wrappers and exports (`seedVowsKnown` local, `FIELDS_KEYS` alias, `namesBoundList` block, unused `SoulgatherState` bindings in ui/actions, `AWAY_MIN_DT`, `VOW_CONFIRM` / `seedVowsKnown` / `fieldDefault` / `dumpNum` / `numFieldBroken` exports, rite-cost BASE aliases, `nightSecs` / `remembranceFavorCost` shims, `TRIBUTE_AUTOBIND_STARTS` Actions re-export); `veilCost` through `VEIL_FRAC`; Quiet Court copy and unlock-flag assignments collapsed; peak fields use `PEAK_STATS`; one clipboard `fillFallback`; `trimFixed1` in format; stale comments dropped.
- Also dropped unread `SoulgatherEconomy` test-dump keys (no test reads them) and dead `resetToScope`.
- The Remembrance shop buyers in `js/prestige.js` now share one `buyRemembranceUpgrade(levelKey, costFn, max, chronicleId)`; each public `buy*` name stays as a one-line wrapper. Identical `*EdictCost` functions use one geometric helper and identical start-count helpers use `startsCount(level, max?)`; exported names and numbers are unchanged.
- Dead-code trim (no behavior change): unread `SoulgatherNum.fromString`/`isZero` and `SoulgatherEconomy.formatGoalNum`/`nextFavorThreshold` export keys (functions stay); unused `siphon-row`/`mark-ember-row` ids; keydown uses `resolveHotkey`; comments that only restated a ticket id plus the next line.
